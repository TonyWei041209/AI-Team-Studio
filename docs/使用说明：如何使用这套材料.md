# 如何使用这套材料

这套材料的目标不是“让 Claude Code 一次性读完所有东西然后自由发挥”，而是**按阶段、按场景、按角色喂给它**。

## 你手上的材料分别做什么

### 1. `CLAUDE.md`
这是项目的**长期行为约束**。

用途：
- 定义项目目标
- 定义第一版边界
- 定义技术栈
- 定义高风险动作规则
- 定义默认工作方式

**什么时候用：**
- 一开始就放进仓库根目录
- 全程保留
- 后续只做增量更新

Claude Code 官方会自动读取项目里的 `CLAUDE.md`，把它当作项目记忆和行为指导。([Anthropic 文档](https://docs.anthropic.com/en/docs/claude-code/memory))

### 2. `.claude/agents/*.md`
这是**角色模板**。

用途：
- 固定 Planner / Builder / QA / Reviewer 的职责和输出格式
- 避免一个 agent 既规划又实现又验收

**什么时候用：**
- Phase 0 就放进仓库
- 从 Phase 3 开始价值最大
- 后续可以继续细化角色规则

Claude Code 官方支持自定义 subagents，并允许为每个 subagent 配不同工具权限和模型。([Anthropic 文档](https://docs.anthropic.com/en/docs/claude-code/sub-agents))

### 3. `START_PROMPTS.md`
这是**你每个阶段真正粘贴给 Claude Code 的启动口令库**。

用途：
- 避免每次重新组织语言
- 限制 Claude Code 只做当前阶段
- 保持节奏稳定

**什么时候用：**
- 每次开启新 session
- 每次进入新 phase
- 每次需要切换到审查模式 / 修复模式

### 4. `Claude_Code_执行计划书_优化版.pdf`
这是**正式冻结版主规格说明书**。

用途：
- 作为总体执行蓝图
- 帮你在大改动前重新校准方向
- 让 Claude Code 在桌面端 / 浏览器端有附件能力时读取完整正式版说明

**什么时候用：**
- 第一次启动项目时
- 每次进入新大阶段时
- Claude Code开始跑偏时
- 你要它重新对齐总目标时

**什么时候不要反复喂：**
- 不要每一次小修小补都重新塞整份 PDF
- 不要在一个很短的小任务里反复附上完整 PDF
- 小任务优先引用 `CLAUDE.md` + 当前相关源码 + 局部 prompt

## PDF 应该怎么喂给 Claude Code

### 最推荐的顺序

#### 情况 A：你在 Claude Code 的桌面端 / 浏览器端用附件
Anthropic 官方文档说明，Claude Code 桌面端 / 浏览器端支持把文件拖进提示框作为附件；对于大 PDF，可以要求 Claude 只读指定页码。([Anthropic 文档](https://docs.anthropic.com/en/docs/claude-code/ide-integrations))

推荐做法：
1. 把 `CLAUDE.md` 和 `.claude/agents/` 先放进仓库
2. 打开 Claude Code
3. 先发“第一次启动”提示词
4. 再把 PDF 作为附件拖进去
5. 明确要求：
   - 先只读取与当前阶段相关的页
   - 不要扩展到后续阶段

推荐话术：

```text
请严格按照仓库内的 CLAUDE.md 执行，并参考我附上的《Claude Code 执行计划书》PDF。
这次只阅读与 Phase 0 和 Phase 1 相关的部分，不要扩展到后续阶段。
开始前先输出：阶段目标、文件改动计划、设计理由、验收标准。
```

#### 情况 B：你在 Claude Code 终端里主要工作
Claude Code 官方说明会自动按需读取项目文件，不需要你手动塞很多上下文；因此在 CLI 场景里，最稳的做法是把长期规则放进 `CLAUDE.md`，把阶段指令放进 `START_PROMPTS.md`。([Anthropic 文档](https://docs.anthropic.com/en/docs/claude-code/quickstart))

推荐做法：
1. 不要指望 CLI 每次都“读 PDF 二进制”
2. 让核心可执行规则落在 `CLAUDE.md`
3. 把 PDF 当作人工查看的正式母版
4. 需要 Claude Code 对齐时，直接说：
   - 请读取 `CLAUDE.md`
   - 请按 `START_PROMPTS.md` 的当前阶段执行
   - 如需总规格，请参考 docs 中整理过的对应章节

也就是说，**CLI 模式下，PDF 更适合做人类主规格存档，不适合做高频主输入。**

## 最佳使用顺序

### 第 0 天：建仓库
放进去：
- `CLAUDE.md`
- `.claude/agents/*.md`
- `START_PROMPTS.md`
- PDF 和 DOCX（存档用）

### 第 1 次启动 Claude Code
只喂：
- `CLAUDE.md`
- `START_PROMPTS.md` 的“第一次启动” prompt
- 如果你在桌面端 / 浏览器端，就附上 PDF

目标：
- 完成 Phase 0 + Phase 1

### 第 2 次启动
只喂：
- `CLAUDE.md`
- 当前代码
- `START_PROMPTS.md` 的“第二次启动” prompt
- 如有必要，再让它参考 PDF 的 Phase 2

目标：
- 完成数据模型与任务系统

### 第 3 次启动
只喂：
- `CLAUDE.md`
- `.claude/agents/*.md`
- 当前 runtime 代码
- “第三次启动” prompt

目标：
- 完成角色层与 orchestrator

## 你最应该避免的做法

1. 一上来就把整份 PDF、所有 prompt、所有想法一次性全贴进去
2. 每个小任务都重新附完整 PDF
3. 没做阶段约束就让 Claude Code“自己决定怎么做”
4. 没有 `CLAUDE.md` 就只靠聊天指令推动长期项目
5. 让 Builder 既写代码又做最终验收

## 一句最实用的原则

**长期规则放 `CLAUDE.md`，角色规则放 `.claude/agents/`，阶段动作放 `START_PROMPTS.md`，PDF 作为正式冻结版总说明，只在开局、换阶段、跑偏纠偏时使用。**
